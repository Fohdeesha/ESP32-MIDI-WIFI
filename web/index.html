Flight recorderEvery USB MIDI packet in both directions and every session, USB and WiFi event, timed to the microsecond. After a session drop, a heartbeat stop, a USB port reset or a WiFi drop it records 10 s more and then stops, so what led up to it is kept until you re-arm it. Pick those triggers under Configuration.

Network scanning is paused while a MIDI session is active -- a scan takes the radio off-channel for seconds and would interrupt the stream. Scan anyway (expect a brief dropout), or just type the SSID above.









Currently bridging . RTP-MIDI carries no port number, so one port is bridged per direction, normally the same one — a control surface expects its LEDs back on the port it sent from. "All ports" merges every incoming port; with it the return path has no port to follow, so pick one explicitly. Plug the device in and reload to see which ports it presents and which are carrying traffic.








A wrong static IP can make the device unreachable (no setup-AP fallback once WiFi itself connects). Recovery: hold BOOT for 10 s to factory-reset.





Power above ~8.5 dBm has been shown to cause brownouts on some ESP32 boards. Use with caution.









Reboot restarts the firmware without touching any settings; the MIDI session drops and re-establishes.


Firmware update




Config import & export






Export saves every setting to a file, including the WiFi and web UI passwords in plain text. Import loads such a file and reboots; settings the file leaves out stay as they are. A file from another board brings its static IP too, so change sip in it first or both boards will share one address.


Factory reset




Also available without the password: hold the BOOT button for 10 seconds.


Device reboots after saving config, importing settings, flashing firmware, or resetting.
